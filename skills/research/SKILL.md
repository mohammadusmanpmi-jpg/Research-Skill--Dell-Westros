# Research

A phased research system for ad creative. Every run starts with a menu so the user only pays for the phases and sources they need. Every phase saves its output to disk so nothing is ever collected twice.

## 0. Start with the menu (always)

Never start researching before the user has chosen a mode. Ask with AskUserQuestion:

**Question 1 – What do you want to run?** (AskUserQuestion allows max 4 options)
1. Full run (Phase 0 → 0B → 1 → 2 → 3 → 4)
2. Competitor & angle gap – competitor teardown + ad intelligence + Phase 3 (needs a brief and a consolidation; runs whichever are missing first, after asking)
3. Pick phases – follow-up multi-select: Phase 0 brief · Phase 0B client account, business and offer audit · Phase 1 collection · Science and authority · Trend scan · Phase 2 consolidation + DRIVE · Phase 3 angles & avatars (incl. the Angle Exploration Document) · Phase 4 DRIVE Strategy Document
4. Re-validate angles – re-run ad searches for angles in an existing `03-angles.md` and update their flags (competitors move; an OPEN angle can be EMERGING a month later)

**Question 2 – depends on the answer:**
- Product URL (and optional extra page URLs) if no brand folder exists yet.
- For Phase 1 / full run: which sources, multi-select. Mark each with its access need (see table in §3). Default selection = every source that works without a login.
- Where an existing output is found (see §2): "Reuse `<file>` from `<date>`, or redo?"

Keep the menu to two or three questions. The point is to stop wasted time, not to add a form.

## 1. Folder layout

All work for a brand lives in `research/<brand-slug>/` under the current working directory:

```
research/<brand-slug>/
  00-extraction.md        Phase 0.1 website extraction
  00-brief.md             Phase 0.2 Research Brief
  00-account.md           Phase 0B – the client's own ads: proven on account, tested and stopped, removed, landing-page map, live claims check
  00-business.md          Phase 0B – traffic trend, white-label clones and price floor, competitor revenue, account health
  00-offer-audit.md       Phase 0B – label, dose and offer audit → "N fixes on the client's side"
  01-quotes.jsonl         Phase 1 – one JSON record per quote, all sources appended
  01-<source>.md          Phase 1 – per-source summary + shortfall report
  01-competitors.md       Phase 1 – competitor website teardown + comparison table
  01-ads.jsonl            Phase 1 – one JSON record per competitor/our ad (TrendTrack or Meta Ad Library)
  01-ad-searches.md       Phase 1/3 – every ad search run, with hit counts (evidence for flags)
  01-ad-matrix.md         generated by scripts/ad_matrix.py – angle/avatar status per competitor ads
  01-ads.md               Phase 1 – ad audit summary
  01-tiktok.md            Phase 1 – TikTok summary (Shop reviews, comments, creators, ads)
  01-trends.md            Phase 1 – trend scan: rising trends in the market, flagged UNRIDDEN / EARLY RIDERS / RIDDEN
  01-authority.md         Phase 1 – academic / regulatory findings
  01-science.md           Phase 1 – science and authority: problem science, ingredient evidence ceiling, drug interactions, claim guardrails, what we don't claim
  01-counts.md            generated by scripts/count_quotes.py (never hand-written)
  01-verification.md      generated by scripts/verify_quotes.py – every quote re-checked against its live link
  01-depth.md             generated by scripts/depth_check.py – each source vs its minimum floor
  02-consolidation.md     Phase 1.13 – 12-section VOC document
  02-drive.md             Phase 2 – DRIVE sections 1-20
  03-angles.md            Phase 3 – angle exploration
  03-mechanism-check.md   generated by scripts/mechanism_check.py – our mechanism lines and hooks vs competitor phrasing
  03-angle-exploration.md Phase 3 – the client-facing Angle Exploration Document (competitor takeover, angle library, trend angles)
  04-drive-strategy.md    Phase 4 – the client-facing DRIVE Strategy Document
  state.json              which phases are done, when, with what inputs
```

On first run, ask the user before creating the folder ("There's no folder for <brand> yet. Shall I create `research/<brand-slug>/`?") and wait for a yes. Slug = brand name lowercased, hyphenated.

## 2. Gating and reuse (how time is saved)

Before running a phase, check `state.json` and the files on disk:

- Output already exists → offer reuse vs redo in the menu. Default to reuse if under 60 days old.
- Required input missing → stop and say which earlier phase to run. Do not improvise a brief from memory to get past the gate.

| Phase | Needs |
|---|---|
| 0 | a URL |
| 0B account, business, offer | `00-brief.md` (asks the client for an Ads Manager export; runs without it from public ad libraries) |
| 1 | `00-brief.md` (and `00-account.md` when 0B was chosen, so the client's proven ads are known first) |
| 1.13 consolidation | `01-quotes.jsonl` with ≥1 source + `01-counts.md` + `01-verification.md` showing 100% checked + `01-depth.md` with every source at its floor or an approved shortfall |
| 2 DRIVE | `02-consolidation.md` |
| 3 angles & avatars | `02-consolidation.md` + `01-ad-matrix.md` (without ad data Phase 3 still runs, but every angle is flagged NOT VALIDATED – tell the user first and offer to run the Ads collector) |
| Re-validate | `03-angles.md` + an ad data source |
| Trend scan | `00-brief.md` (for keywords); runs on its own or inside Phase 1 |
| Science and authority | `00-brief.md` (+ `00-offer-audit.md` for ingredient amounts) |
| 3 Angle Exploration Document | `03-angles.md` + `03-mechanism-check.md` with 0 REWORD lines |
| 4 DRIVE Strategy | `02-drive.md` + `03-angles.md` + `01-science.md` + `00-account.md` / `00-offer-audit.md` (if 0B was skipped, the document says so and lists the client-side checks as not done) |

Update `state.json` after each phase: `{ "phase": "...", "done_at": ISO date, "inputs": [...], "sources": [...] }`.

## 3. Sources and access

| Source | Access | Collector file |
|---|---|---|
| Reddit | open (old.reddit.com / .json endpoints) | phase1-collectors.md §Reddit |
| Niche forums, patient.info, etc. | open | §Forums |
| YouTube comments | open (page / API-less scrape, limited) | §YouTube |
| Trustpilot, BBB, ComplaintsBoard, Sitejabber, ProductReview.com.au | open | §Complaints |
| Google Scholar, PubMed, Cochrane, regulators | open | §Authority |
| Science: ingredient evidence, drug interactions (NIH ODS, MedlinePlus, Drugs.com, LiverTox, NCCIH) | open | science-collector.md |
| Health communities (Mayo Clinic Connect, Drugs.com reviews, HealthUnlocked, WebMD, Inspire, MedHelp, niche forums) | open | §Forums + sources.md |
| Client's own ad account | TrendTrack / Meta Ad Library / client export | phase0b-account-business-offer.md |
| Google autocomplete / People Also Ask | partial – often blocked | §Google |
| Amazon reviews | partial – often blocked, better in browser | §Amazon |
| Quora | partial – needs login for most content | §Quora |
| Competitor websites | open | §Competitors |
| Competitor ads | **TrendTrack MCP** (preferred) or Meta Ad Library in browser | §Ads |
| Facebook Groups, TikTok, Instagram, X | **browser only** (logged-in Chrome via Claude in Chrome) | §Social |
| TikTok – Shop reviews, video comments, creators, ads | TrendTrack `search_tiktok_library` (ads + organic) and/or browser | tiktok-and-trends.md § A |
| Trends – Google Trends, TikTok Creative Center, local news, local marketplaces | open / partial (Creative Center partly needs browser) | tiktok-and-trends.md § B |

Detect which tools exist: browser (`mcp__claude-in-chrome__*`) and ad intelligence (`mcp__Trendtrack__*`). Mention in the menu which ad source will be used. If TrendTrack is present, call `check_credits` and add a menu question for the credit budget of this run (e.g. ~150 quick / ~400 thorough / custom); follow the TrendTrack playbook in phase1-collectors.md §Ads. TrendTrack's `search_tiktok_library` also gives TikTok ad/organic creatives without the browser. If they do not, grey out browser-only sources in the menu and say so in one line. Never run a browser-only collector without the browser: it cannot produce real quotes, and fabricated quotes poison every later phase.

Open-access collectors can run in parallel as subagents (one per source). Browser collectors run one at a time, in the main session, paced (max ~40 page loads per source per run) to protect the user's accounts.

## 4. The one rule that matters: no invented data

Everything downstream (frequency bands, angles, test order) is only as good as the quotes. So:

- Every quote is verbatim, with a URL, date and platform. No URL → not recorded.
- Every source has a **minimum depth floor** (quotes, threads, communities; see phase1-collectors.md § Minimum depth). A collector keeps going until it meets its floor **and** reaches saturation. If the floor truly can't be met after every query, sub-community and page route has been tried, it writes a shortfall note listing everything searched and what blocked it, and the user is asked before Phase 2 starts. A collector never pads: a quote that isn't real is worse than a missing one.
- Counts come from `scripts/count_quotes.py`, never from estimation. Consolidation reads `01-counts.md`.
- After collection, **re-check every quote against its live link** with `scripts/verify_quotes.py` (100%, not a sample). Quotes not found are removed; quotes on pages the script can't reach are re-checked in the browser or removed. Record the result in `01-verification.md`. Then run `scripts/depth_check.py` and save it as `01-depth.md`. Research is not done while any quote is unchecked or any source is below its floor without an approved shortfall.

## 5. Phase files – read the one you need

- `references/phase0-website-brief.md` – Prompts 0.1 and 0.2, with category-adaptive query groups.
- `references/phase1-collectors.md` – per-source collection instructions and the quote record format.
- `references/phase1-consolidation.md` – the 12-section consolidation (Prompt 1.13).
- `references/phase2-drive.md` – DRIVE prompts 2.1–2.5.
- `references/phase3-angles.md` – angle exploration module.
- `references/definitions.md` – Life Force 8, awareness levels, sophistication stages, hook types, proof types, Default Desire Trap checks. **If the user supplies their own framework, replace this file; the phases reference it by name.**
- `references/sources.md` – every platform URL and search-page URL.
- `references/tiktok-and-trends.md` – the TikTok collector (Shop reviews, comments, creators, ads) and the trend scan (Google Trends, TikTok trends, local news, marketplaces), all filtered to the target market, with UNRIDDEN / EARLY RIDERS / RIDDEN flags.
- `references/phase0b-account-business-offer.md` – Phase 0B: the client's own ad account (iterate proven ads first), business context, and the label, dose and offer audit.
- `references/science-collector.md` – the science and authority collector (about 50 sources, evidence ceiling per ingredient at the real dose, drug interactions, claim guardrails, what we don't claim).
- `references/angle-exploration-template.md` – the client-facing Angle Exploration Document, with the required competitor takeover section ("This angle is currently running from [competitor]" → "Here's how we dominate it"), the angle library and trend angles.
- `references/drive-strategy-template.md` – Phase 4: the client-facing DRIVE Strategy Document (executive summary, client-side fixes, the DRIVE parts, ICP cards, angle cards, appendices).
- `references/course-playbook.md` – David Briggs course methods for every phase (review reading, extra sources, market diagnostic, mechanism build, belief pairs, persona split, hook frameworks, open loops, results diagnostics). Each phase file says which section to read.

## 6. Running a phase

**Phase 0** – fetch the URL(s) with WebFetch (browser if JS-heavy). Write `00-extraction.md`, then `00-brief.md`. Show the user the brief's summary block and ask for a go-ahead before Phase 1 (the brief decides every search; a wrong brief wastes the whole collection).

**Phase 0B** – follow `phase0b-account-business-offer.md`. Pull the client's own ads first, then business context, then the offer audit. Write `00-account.md`, `00-business.md`, `00-offer-audit.md`, and show the user the "N fixes on the client's side" list.

**Phase 1** – for each chosen source, follow its collector section. Write records to `01-quotes.jsonl` (append) and a per-source summary. Then run:

```
python scripts/count_quotes.py research/<brand>/01-quotes.jsonl > research/<brand>/01-counts.md
```

Run the TikTok collector and the trend scan with the other sources (tiktok-and-trends.md), and the science collector (science-collector.md → `01-science.md`). Then verify every quote and check depth:

```
python scripts/verify_quotes.py research/<brand>/01-quotes.jsonl > research/<brand>/01-verification.md
python scripts/count_quotes.py research/<brand>/01-quotes.jsonl > research/<brand>/01-counts.md
python scripts/depth_check.py research/<brand>/01-quotes.jsonl research/<brand>/01-ads.jsonl > research/<brand>/01-depth.md
```

Show the user the `01-depth.md` table before consolidation. Then consolidation (`phase1-consolidation.md`) → `02-consolidation.md`.

**Phase 2** – read `02-consolidation.md` + `definitions.md`, run 2.1→2.5 in order, write `02-drive.md`.

**Phase 3** – read `phase3-angles.md`, write `03-angles.md`. Core idea: competitors research too, so every angle carries a validation flag backed by logged ad searches; angles competitors already run are not dropped but get a take-over plan (unique mechanism, new avatar, sharper words); avatars competitors ignore are surfaced from the avatar gap map. The client's own proven ads are iterated first. Check our mechanism lines and hooks against competitor phrasing:

```
python scripts/mechanism_check.py research/<brand>/01-ads.jsonl ours.txt > research/<brand>/03-mechanism-check.md
```

Then write the client-facing `03-angle-exploration.md` from `angle-exploration-template.md`: every angle a competitor runs now gets a takeover card ("This angle is currently running from [competitor]" with exact copy, ad link, days running and target, then "Here's how we dominate it"), followed by the open angle library and the trend angles.

**Phase 4** – write `04-drive-strategy.md` from `drive-strategy-template.md`: executive summary, client-side fixes, the DRIVE parts, ICP cards, angle cards and appendices.

**Re-validate** – for each angle in `03-angles.md`, rerun its logged searches, append new ads, rerun `ad_matrix.py`, update flags and note what changed at the top of the file.

End every run with a short status: which files were written, quote count per source, shortfalls, and the single next step.

## 7. Output

Deliverables are markdown files in the brand folder. If the user asks for a shareable version, publish `02-consolidation.md`, `02-drive.md`, `03-angles.md`, `03-angle-exploration.md` or `04-drive-strategy.md` as a doc or artifact; otherwise leave them as files.
