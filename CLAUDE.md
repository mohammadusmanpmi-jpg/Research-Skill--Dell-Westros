# Research projects

For any product, brand or competitor research for ads in this or any project folder:

- Read the `client-research-workflow` skill first, then use the `research` skill (`/research`). Start with its menu; do not research ad hoc outside it.
- Keep each brand's work in `research/<brand-slug>/` inside the current project folder, and reuse what is already there before collecting again.
- Never invent quotes, counts or competitor ads. No source URL means it is not recorded; sources that can't be reached are reported as shortfalls.
- Research is not done until every source meets its minimum depth floor (or has a logged shortfall the user has seen) and every quote has been re-checked against its live link (`verify_quotes.py`, 100%).
- Every angle suggested must carry a competitor validation flag (OPEN / EMERGING / PROVEN / CROWDED / ABANDONED / NOT VALIDATED) with the ad searches behind it. Angles competitors already run are not dropped: give a take-over plan (unique mechanism, new avatar, new proof, sharper words).
- Use TrendTrack MCP for competitor ads when connected, otherwise the Meta Ad Library in Chrome.
- Always include TikTok (Shop reviews, comments, local creators, TikTok ads) and a trend scan of the target market (Google Trends, TikTok trends, local news), flagging trends competitors aren't riding yet.
- A full run starts with the client's own ad account (iterate proven ads before inventing new ones), the business context and a label, dose and offer audit, and includes a science and claims check for health products.
- Client-facing output follows Dell's documents: the DRIVE Strategy Document (`drive-strategy-template.md`) and the Angle Exploration Document (`angle-exploration-template.md`). Every angle a competitor runs gets "This angle is currently running from [competitor]" (exact copy, ad link, days running, target) and "Here's how we dominate it". Use Dell's terms: ICP, Mechanism (problem + solution), Angles, Hooks.
